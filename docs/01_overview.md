# Overview

**Problem statement SIH26147 — "Automated Model for Analysis of .IQ and .WAV Files Along with Signal
Parameter Extraction".**

This repository is a working platform, not a mock-up. Every number displayed by the UI is produced by
an estimator in `dsp/` from the bytes the user uploaded; no chart is decorative, no confidence is
random, and every automatic statement carries its evidence and its limitations.

> **One-line summary:** upload a `.iq`/`.wav` capture — or generate one — and the platform identifies
> the container and sample format, analyses the spectrum and spectrogram, finds the emissions,
> estimates the parameters, classifies the modulation, demodulates the signal blind, tests FEC and
> interleaver hypotheses, analyses the recovered bitstream, and exports a report; every step is
> inspectable and every uncertainty is stated.

## What the platform actually does

| Capability | Where | Backend |
| --- | --- | --- |
| Upload `.iq`, `.wav`, complex IQ binary; honest metadata (missing ⇒ `Unknown / requires estimation`) | Analyze Signal, Signal Explorer | `routes/files.py`, `dsp/iqformats.py` |
| Format detection (7 dtypes, interleaved/separate I/Q, endianness) with confidence + evidence + manual override | Signal Explorer | `dsp/iqformats.detect_format` |
| Preprocessing (DC removal, detrend, normalise, LPF/BPF/HPF, resample, denoise, window) with before/after | Analyze → Preprocessing | `dsp/preprocess.py` |
| Spectrum / PSD / peak / occupied bandwidth / noise floor / SNR / carrier / offset, interactive | Analyze → Spectrum | `dsp/spectrum.py` |
| Waterfall + spectrogram with detected regions, zoom, region → re-analysis | Analyze → Waterfall | `dsp/waterfall.py` |
| Multi-signal detection (start/end, centre, bandwidth, peak power, SNR, confidence) with click-to-analyse | Analyze → Detection | `dsp/detect.py` |
| Parameter extraction (symbol rate, deviation, amplitude/phase statistics, …) each with value/confidence/method | Analyze → Parameters | `dsp/params.py` |
| Hybrid modulation classification (DSP rules + measured constellation evidence + spectral/statistical features + optional ML vote) | Modulation | `dsp/modulation.py` |
| Constellation analyzer (raw/filtered/symbol-sampled, clusters, EVM) and eye diagram (timing quality, eye opening) | Analyze → Constellation & eye | `dsp/modulation.py`, `dsp/demod.py` |
| Modular demodulator (BPSK/QPSK/8PSK/16QAM/64QAM/2FSK/GFSK/AM/FM) with per-stage success/failure | Demodulation | `dsp/demod.py` |
| **Blind Analysis Mode** — no user-supplied modulation, symbol rate, carrier offset, FEC or interleaving | Blind Analysis | `dsp/pipeline.py` |
| **Multi-hypothesis analysis** — ranked candidate pipelines with the measurements behind each | Analyze → Evidence | `dsp/hypothesis.py` |
| **FEC hypothesis testing** (convolutional/Viterbi, Reed–Solomon, concatenated; LDPC explicitly unsupported) | FEC / Interleaving | `dsp/fec.py` |
| **Interleaving hypothesis testing** (block, convolutional, diagonal, pseudo-random) | FEC / Interleaving | `dsp/interleave.py` |
| Bitstream analysis (bits, hex, byte distribution, entropy, runs, repeated structure, printable-ASCII *candidate*) | Bitstream | `dsp/bitstream.py` |
| Correlation search for a user-supplied header/pattern + automatic repeated-structure candidates | Bitstream, Analyze → Bitstream | `dsp/correlate.py` |
| Evidence graph, Analysis Confidence System, Signal Quality Report | Analyze → Evidence, Reports | `dsp/pipeline.py`, `backend/app/reports.py` |
| Signal comparison and historical analysis | Compare Signals, History | `dsp/compare.py` |
| Synthetic generator (all modulations, configurable, downloadable, with ground truth) | Synthetic Generator | `dsp/synth.py` |
| Self-benchmark with confusion matrix | Benchmark | `dsp/benchmark.py` |
| Reports: PDF / JSON / CSV / TXT | Reports | `backend/app/reports.py` |

## Run it

```bash
# 1 - containers (builds the front-end and the API)
docker compose up --build
#    UI           http://localhost:8000
#    Swagger UI   http://localhost:8000/docs
#    ReDoc        http://localhost:8000/redoc
#    this folder  http://localhost:8000/documentation

# 2 - local development
python3 -m pip install -r requirements.txt
uvicorn backend.app.main:app --reload --port 8000        # API + built UI
cd frontend && npm install && npm run dev                # Vite dev server on :5173 (proxies /api)
```

Nothing else is required: the demo signals in `sample_data/` are generated by the repository's own
generator, the database is created on first start (`data/app.db`), and the optional machine-learning
vote degrades gracefully to "not available" if no model file is present.

## The judge flow (SIH DEMO MODE)

`http://localhost:8000/demo` walks a reviewer through the whole story in eight steps, and every step
performs real work: **Problem → Upload a demo signal → automatic analysis → AI/DSP reasoning →
3-D pipeline visualisation → results → innovation → benchmark → report**. See
[The judge script](09_sih_demo.md) for exactly what to click and what the platform is expected to
report.

## What is *not* claimed

* No perfect decoding of an arbitrary unknown protocol. The platform recovers bits, **tests**
  hypotheses (modulation, FEC, interleaving, frame structure) and reports what the measurements
  support — including "unable to estimate reliably".
* No "AI magic": the classifier is a hybrid of classical DSP features, measured constellation EVM and
  an optional scikit-learn vote. The ML model is a contributor, never the only decision path, and its
  measured accuracy is stated in the UI (`GET /api/models`).
* No invented metadata: parameters that are absent from the file are reported as
  `Unknown / requires estimation`, and every frequency-derived value is flagged when the sample rate
  had to be estimated.
* No "detected message": recovered bytes are reported as a *printable-ASCII candidate* with a match
  score, never as a decoded text.

## Repository layout

```
backend/app/    FastAPI application: routes, services, models, jobs, reports, storage
dsp/            the DSP engine (format detection → spectrum → detection → params → AMC → demod → FEC → bits)
ml/             classical-ML modulation classifier (training script + joblib model)
frontend/       React + TypeScript SPA (Vite build served by FastAPI)
tests/          pytest suite + end-to-end HTTP smoke test
sample_data/    six bundled demo signals with GROUND_TRUTH.json
docs/           this documentation (also served at /documentation)
docker/         Dockerfile(s), entrypoint and compose helpers
docker-compose.yml
```

## Technology

| Layer | Choice | Why |
| --- | --- | --- |
| DSP | NumPy + SciPy | every estimator is inspectable, no black boxes |
| ML | scikit-learn RandomForest (PyTorch optional, not required) | small CPU-friendly model, honest accuracy reporting |
| API | FastAPI + Uvicorn | typed request models, automatic OpenAPI |
| Storage | SQLite by default, PostgreSQL via `SIH_DATABASE_URL` | zero-setup demo, container-ready for production |
| UI | React 18 + TypeScript + Vite + Plotly | interactive charts without external services |
| Packaging | Docker + docker-compose | `docker compose up --build` is the whole install |
